# Symphony

Symphony is the sole authority for topology, delegation, lifecycle, reassessment, and completion. Keep the root thin.

**Invocation:** Codex uses `$symphony:symphony ...`; Claude Code uses `/symphony:<command>`. Codex does not support `/symphony:*`.

**Assessor boost:** Codex uses `$symphony:symphony boost [xhigh|max|ultra|off]`; Claude uses `/symphony:boost [xhigh|max|off]`. With no argument each requests its highest native level. This changes only subsequent assessors in the current project/provider/session. `off` or `reset` restores normal high assessment. Unsupported provider or account/model efforts are rejected without changing the preference. Use the exact requested/effective native model and effort reported by the hook or status: Claude selects the packaged assessor agent; Codex passes model and reasoning effort explicitly with `fork_turns="none"`. Worker/lead matrix routes, consent, and Fable access/billing opt-in remain unchanged.

## Root loop

1. **Check activation.** On Codex, from the project directory run `python3 -I "<loaded plugin root>/scripts/check_activation.py"` on Linux/macOS or `python.exe -I "<loaded plugin root>/scripts/check_activation.py"` on Windows. Use the plugin root shown in this skill's loaded path. A newly loaded checker can accept this session's older heartbeat after an update only when its retained runtime passes the content digest check. If an update removed the loaded root, use the verified launcher command supplied by the hook, including its original loaded root and `--check-activation`; the heartbeat must also match that retained runtime. Use its retained root for vanished Symphony reference files. Its read-only result checks `CODEX_SESSION_ID`, project, plugin version/root, hook schema, and observation time. A missing dedicated tool is not evidence of a missing heartbeat. Call a run guarded only on a matching result. If verification is pending, explain the native recovery step once and offer an explicitly unguarded one-shot route. Read [provider activation](references/provider-activation.md) for installation, trust, reload, policy, or fault branches.
2. **Clarify at the root.** Agents cannot ask the user anything. When intent or design needs clarification, use a currently callable and compatible brainstorming skill (for example Superpowers `brainstorming`), or make a concise brief and ask only unresolved material questions. Relay the agreed outcome, constraints, assumptions, and success criteria in full. User-facing finishing steps after the lead returns also stay at the root.
3. **Classify.** Treat controls as inert. Send substantive or uncertain work to a bounded assessor with the strongest model accessible under the accepted account profile and explicit effort (normally `high`, or the session boost’s effective effort). The run begins when that assessor is spawned: a prompt on its own opens nothing, so answering directly leaves the turn ungoverned rather than blocked. Every managed spawn follows [role contracts](references/role-contracts.md). Claude rejects an invalid spawn before launch; Codex validates native lifecycle facts and withholds completion when required result markers are missing.
4. **Resolve.** Use the fixed matrix and the freshest available model-capability snapshot. For optional practices, read [capability routing](references/capability-routing.md): select only an exact skill or tool advertised and usable in this session, read its instructions, and check compatibility with the packet. A cache path or prior session is not availability evidence. Use the listed native practice for an absent, disabled, failed, or incompatible capability. Name applicable practices and acceptance evidence in the lead packet. Aggregate material missing-capability advice into one concise notice when useful; do not delay the route.
5. **Delegate.** Announce the route, spawn and register one lead with an explicit model and effort, relay the bounded packet, then wait through the host's wait/result primitive. On Claude Code agents run in the background: end the turn after a spawn and the host wakes the root with the result; never poll with Bash, sleep, Monitor, or the agent's output file. Name each spawned role `symphony_<role>_<model>_<effort>` when the host supports names, and announce `Delegating: <role> [<model>/<effort>] — <identity> — <objective>` from observed spawn facts. Repository inspection, implementation, specialist judgment, integration, and verification belong below the root.
6. **Reconcile.** Record host-observed lifecycle facts. Reassess only at a material evidence boundary; preserve active ownership and replace a lead only through a safe recorded transition. For a retryable Codex lead, first use `followup_task` with the exact underscore-separated `task_name` passed to `spawn_agent`; a `/root/` path or agent UUID is not a valid target. Replace that lead only after the host confirms it is unavailable.
7. **Complete.** Return the lead's integrated outcome only after it has returned and no tracked work remains active. Check the lead's phase evidence and fresh verification; disclose missing checks or scoped exceptions instead of claiming verified success. On Codex, finish the root turn so its native Stop hook can check and archive the run; writing `$symphony:symphony stop` inside an assistant turn does not submit a new user prompt. On Claude, invoke normal `/symphony:stop` in this session. A `completing` run is waiting for that finalization; do not poll it for `completed` or follow up or replace a completed lead solely because it remains `completing`. The normal Stop guard checks current ownership, pending events, and native turn freshness before archiving. If it blocks, reconcile the stated unfinished work and retry normal Stop. Report a run as completed only when durable status confirms it; otherwise report the work and pending checks without claiming lifecycle completion. Keep `SYMPHONY_ASSESSMENT`, `SYMPHONY_ROUTE`, `SYMPHONY_DECISION`, and `SYMPHONY_OUTCOME` markers out of user-facing answers. A host stop is blocked at most once per turn; a repeated stop releases the turn while preserving unfinished work for later reconciliation. It does not prove that agents ended or abandon the run. Only an explicit force stop archives unresolved work. Report only host-observed model, effort, lifecycle, token, and duration facts; omit unavailable metrics. Skill use and practice evidence are agent-reported unless the host exposes a matching event.

On Claude Code, model and effort come from the packaged `symphony-<role>-<model>-<effort>` agent type; never use a generic Agent because its call cannot pin effort. On Codex, pass model and reasoning effort explicitly and use the equivalent underscore-separated task name.
